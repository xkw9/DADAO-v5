# Workflow — DADAO-v5 自有开发流程（`.xkw`）

> 本文件是 `/plan` `/dispatch` `/complete` 命令的**流程规则唯一来源**，命令模板只引用本文与关键路径。
> `.tao/`（克隆来的交互目录）仅作**只读参考**，不得修改；本文可按需自主演进。
> 全局沟通约定仍以全局 AGENTS.md 为准。

## 目录结构

```
.xkw/
├── tasks/<module>/      # 任务文件 <PREFIX>-nnn<suffix>-描述.md
└── knowledge/           # MEMORY.md（状态摘要）、workflow.md（本文）、changelog.md、adr-*.md、contract-*.md、deferred.md、milestones.md
```

模块与任务编号前缀沿用 `.tao/README.md` 语义（`infra=INFRA`、`spec=SPEC`、`testcases=TESTCASES`、`golden=GOLDEN`、`llvm=LLVM`、`qemu=QEMU`、`integ=INTEG`、`gem5=GEM5`、`sail=SAIL`），模块内三位递增。

## 编号空间（与 `.tao` 分离）

`.tao/` 是只读参考且**已占用** `INFRA-001k`~`014m`、`INTEG-001k`~`004m`、`adr-0001`~`0011`。为避免跨树引用歧义与撞号，`.xkw/` **另起号段**（2026-09-25 用户裁定）：

| 类别 | `.xkw` 号段 | 首个 | `.tao` 占用 | 说明 |
| --- | --- | --- | --- | --- |
| 任务 | **`1xx`** | `INFRA-101k` / `INTEG-101t` | `001`–`014` | 三位编号、模块内递增的约定不变，仅换号段 |
| ADR | **`1xxx`** | `adr-1001` | `0001`–`0011` | 四位编号，此后**递增**（下一个是 `adr-1002`） |

两棵树的编号空间**互不占用**，故引用时须写全路径前缀（`.xkw/knowledge/adr-1001-…` vs `.tao/knowledge/adr-0006-…`），不要只写裸编号。

`.xkw/` **纳入版本库**（不写入 `.gitignore`）：任务书与知识库随仓库提交，决策与门禁可审计；宿主侧产物（`.cache/`、`.work/`）仍由根 `.gitignore` 排除。

任务后缀状态机：

- `k` = 启动（澄清目标 + 分解任务）→ `待开始` → `已验证`（/plan 审查通过后，不单独验收）
- `t` = 普通任务 → `待开始` → `待验收` → `已验证`（`待返工` 回退）
- `m` = 里程碑标记（轻量）→ `待开始` → `里程碑`

跨模块交互：里程碑核验须考虑其它模块影响；受影响需修复时，里程碑**后移**或新增交互任务，不得将里程碑置为「里程碑」而留未处置影响。

## /plan 流程

1. 读 `.xkw/knowledge/MEMORY.md` 与 `README.md` 了解当前状态；`.tao/` 作只读参考。
2. 用 `task` 调 **architect** 子代理规划，产出任务文件草案到 `.xkw/tasks/<module>/`（任务书须**自包含**：目标/范围/约束/验收之间不自相矛盾；验收逐条标注「现在可跑 / BLOCKED（原因 + 替代证据）」）。
3. 用 `task` 调 **reviewer** 子代理交叉审查任务书。
4. 审查通过后落盘，更新 `MEMORY.md`。
5. 涉及 ADR 判据（不可逆、跨模块、多方案、外部契约、结论固化）时，**主动提醒用户是否生成 ADR**；decision 须**逐条经用户确认**后才可写入 ADR。

## /dispatch 流程（含四项强制预检）

执行任何具体任务之前，**必须先与用户确认任务书内容**；确认后方可下发。

1. 读取目标任务书（`.xkw/tasks/**/<任务ID>`）。
2. **四项预检**（必做，结论随下发说明给出）：
   1. **任务书内部一致性**：目标/范围/约束/验收之间不得自相矛盾。
   2. **依赖链实际可用性**：本任务验证手段所需的全部前置（含跨任务的指令/工具）须已具备；「已验证」≠「任务所需能力已具备」。
   3. **验收可执行性**：逐条标明「现在可跑」或「BLOCKED（原因 + 替代证据）」。不可跑者必须写明替代验证方式（最小 ROM 探针 / 独立 oracle / 仓库向量回放），**不得留下"跑不了就报 PASS"的空间**。
   4. **与 spec/vectors 一致**：指令范围、编码、期望值来源须与 `contracts/`、`tests/vectors/` 对得上。
3. **用户确认**：预检结论 + 任务书全文提交用户；逐条澄清（一次一个问题，依回答追问）直到完全理解。
4. 用 `task` 调 **engineer** 子代理执行。
   - 子代理返回异常（`Task cancelled` / 空结果）时：**先核对任务文件「完成区」与 `git status`**——产出已落盘则视为完成继续 `/complete`；确未落盘则停止汇报。**不得自行重试**（避免重复执行）。
   - engineer **连续 ≥3 次**空返回且产出未落盘时，主会话**可代行完成修改**，但仍须经 reviewer 独立验收；事件登记 `deferred.md`（task_id、空返回次数、代行内容与验收结果）。
5. 完成后状态置 `待验收`；复杂验证类命令输出 tee 到 `.work/log/<模块>/<任务ID>-<命令名>.log`。

## /complete 流程（含反例门控）

1. 用 `task` 调 **reviewer** 子代理验收：
   - **验证脚本必须能失败**：对每个用于验收的验证脚本/检查器，**亲自注入反例**（改错期望值、改错编码、把实现回退为桩）并确认其报 FAIL；**不得仅复跑脚本见 PASS 即判通过**。
   - 每条断言/用例都须有**可达的 FAIL 路径**（两支写同一结果、恒真断言、分支偏移指向 PASS 分支等结构必须逐用例核对，**全文件排查同类**，不得只改点名那条）。
   - 注入后须验证 `git diff --name-only` **非空**（防止空注入假结论）；注入后**必须还原且还原须包含重建**（源码还原 ≠ 二进制还原），给出还原证据，不得在污染的工作区/二进制上验收。
   - 独立 oracle（`-d cpu` 寄存器 dump、仓库独立向量回放等）承担语义正确性；覆盖/桩检查只证明「实现存在」，不得作为语义证据。
   - 完成区结论须与真实输出**逐条对齐**，不得转述/概括/矛盾。
   - 数据/期望值类任务：size/sign 敏感用例（定宽有符号 add/sub/mul/div/rem、div/rem truncate-toward-zero 等）**逐条独立重算**比对，**不是抽样**；不以 validator 绿灯为唯一判据；错值**当场修复**，不得标遗留。
   - 探针分支须双向验证：全文件逐条核对分支目标 + 给出「仅令该断言比较值错 → FAIL」的真实输出。
2. 用 `task` 调 **architect** 子代理交叉复核。
3. 结论处理：Needs Revision → 状态回 `待返工` 并列出缺陷；Accepted → 知识沉淀（`MEMORY.md` / `changelog.md`），状态置 `已验证`。
4. 涉及 ADR 判据时提醒用户；ADR 的每个 decision 逐条经用户确认后方可写为 Accepted。

## 日志留存

- `.work/log/<模块>/<任务ID>-<命令名>.log`；reviewer 重跑加 `-review-`。
- 命令正常结束时用 `tee` 同时输出到终端和日志。

## 临时目录

- 所有临时/合成测试/一次性产物放 `/tmp/opencode/<任务ID>/`，不另起 `/tmp/<其它名>`，不得放仓库内或 `~/`。
- 生成器/脚本随产物保留：产物入库（git）的生成器/脚本必须一并保留在非易失位置——优先 `tools/<module>/`，否则 `.work/<任务ID>/`；**不得只放 `/tmp`**。

## ADR 提醒（判据速查）

不可逆、跨模块、多方案、外部契约、结论固化、定位——命中即提醒用户是否生成 ADR；不擅自决定、不静默略过。格式见 `.tao/knowledge/adr-authoring.md`（只读参考）。

## 大文件下载

需从国外站下载较大软件（LLVM、QEMU、linux-kernel 等）：先查教育网镜像站列表，逐个测连通性与速度后综合给出建议（含直连作对照），**由用户确定从哪个站下载**，不得自行选定并开始下载。细则见 `.tao/knowledge/mirrors.md`（只读参考）。
