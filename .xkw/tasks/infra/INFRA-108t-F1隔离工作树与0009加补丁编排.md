# INFRA-108t: F1 隔离工作树与 0009+ 补丁编排

**模块**：infra

**状态**：已验证  
**依赖**：M1 复现基线 `INFRA-104t`~`106t` 已验证；ADR-1004

## 目标

在不触碰 M1 可复现源码树、构建树和 `0001`–`0008` 补丁的前提下，为 LLVM/QEMU 建立 F1 隔离源码/构建入口和 append-only `0009+` 系列编排。

## 固定布局与基线

- M1 冻结：`.work/source/{llvm-project,qemu}`、`.work/build/{llvm,qemu}`、两组件既有 `components/*/patches/0001`–`0008`。
- F1：`.work/f1/source/{llvm-project,qemu}`、`.work/f1/build/{llvm,qemu}`。
- 每棵 F1 源码树必须从对应 M1 8-patch 头建立；记录 base lock、8-patch head tree/commit、F1 head、patch count 和 clean 状态。
- F1 组件变更仅进入各自 `0009+` patch；仓库侧 `tests/`、`tools/`、向量、contract 不打进上游 patch。

## 交付物

1. 扩展 `tools/infra/` 与 Makefile 的显式 F1 fetch/apply/build/check 入口；默认 M1 目标行为不得变化。
2. 两组件 F1 series 约束：编号连续、无覆盖 0001–0008、patch 可离线从本地 mirror/锁定对象重放。
3. 基线保护 checker：比较行动前后 M1 源/构建关键哈希、patch 1–8 sha256 和 M1 747 测试基线输入。
4. 构建日志写 `.work/log/infra/INFRA-108t-*`；临时重放树只在 `/tmp/opencode/INFRA-108t/`。

## 资源与冲突

LLVM 与 QEMU 源码树逻辑独立，但宿主内存历史最低余量极紧；configure/build/link 必须串行，链接并行度维持安全值。不得同时执行 M1 与 F1 大构建。下载或新增大镜像必须按镜像规则另行询问；本任务优先复用现有锁定 bare mirror，不联网。
